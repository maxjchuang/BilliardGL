# BilliardGL 物理真实性验证体系设计

日期：2026-07-13

## 1. 目标

为 BilliardGL 建立一套可自动执行、可量化、可追溯的物理真实性验证体系。该体系以 WPA 美式 Pool 器材规格为唯一主要基准，以论文和公开实验数据作为真实世界 ground truth，并验证台面内 2.5D 物理：球心在台面二维平面运动，同时计算完整三维角速度。

验证结论不能只依赖视觉观感。每项“符合真实世界”的结论必须能够追溯到解析物理约束、公开实验数据或明确标注证据局限的工程验收标准。

## 2. 范围

### 2.1 包含

- 球的滑动、滚动、停止以及滑动到纯滚动的转换。
- 中心击球、高杆、低杆、左右侧旋和组合旋转。
- 球球正碰、斜碰、带旋碰撞和多球近似同时碰撞。
- 球撞库边的速度损失、反弹角和旋转传递。
- 袋口几何、袋角接触、进袋和拒球边界。
- 开球、连续碰撞、进球、母球落袋和完整游戏状态集成。
- 时间步、渲染帧率、球编号和执行负载对结果的影响。

### 2.2 不包含

- 跳球、扎杆、腾空、落台和飞出台面的完整三维刚体运动。
- 球体、台呢和库边的有限元形变模拟。
- 以斯诺克器材参数直接验收美式 Pool 的数值结果。
- 将玩家主观观感或单段录像作为物理正确性的唯一证据。

## 3. 基准与证据等级

### 3.1 器材基准

球桌尺寸、球直径、袋口和其他器材几何以 [WPA Recommended Equipment Specifications](https://wpapool.com/wp-content/uploads/2024/01/RECOMMENDED-EQUIPMENT-SPECIFICATIONS.pdf) 为准。项目当前约 `254 cm × 127 cm` 的比赛区域和 `57.15 mm` 球直径按美式 Pool 解释。

斯诺克论文可以验证模型趋势、算法结构和参数数量级，但不得把斯诺克的摩擦、恢复系数或库边参数未经换算直接作为美式 Pool 的通过标准。

### 3.2 证据等级

| 等级 | 定义 | 用途 |
|---|---|---|
| A | 论文提供可复现的实验条件、测量精度和轨迹或逐点数据 | 直接验收轨迹、速度、角速度或事件时间 |
| B | 理论模型经过真实台球实验对照，但原始数据不完整 | 验收派生指标、趋势和参数范围 |
| C | 只有理论推导、器材几何或公开视频 | 验证不变量、边界和定性趋势，不单独证明数值真实性 |

初始参考资料包括：

- Mathavan、Jackson、Parkin 的[高速摄影实验](https://doi.org/10.1119/1.3157159)，用于滚动/滑动摩擦、球球斜碰和垂直撞库。
- Doménech 等人的 [independent friction-restitution 模型及标准台球实验](https://doi.org/10.1016/j.mechrescom.2023.104149)，用于带旋球球碰撞。
- Mathavan 等人的[库边动力学模型及实验对照](https://drdavepoolinfo.com/physics_articles/Mathavan_IMechE_2010.pdf)，用于球撞库边。
- Cross 的[球杆击球实验](https://doi.org/10.1177/17543371231184011)，用于球杆击点、初始线速度、角速度和滑杆边界。

引入任何参考数据时，必须记录作者、标题、链接或 DOI、页码/图号、实验器材、单位、数字化方法、测量不确定度、许可信息和证据等级。

## 4. 验证架构

系统分为五个边界清晰的模块：

### 4.1 Physics Scenario

用版本化、机器可读的格式描述：

- 球桌与器材规格；
- 每个球的位置、线速度、角速度和活动状态；
- 球杆位置、方向、速度、击点和力度；
- 固定物理时间步、模拟时长与停止条件；
- 需要记录的事件和验收指标。

同一场景定义必须能够被物理核心测试和完整游戏 E2E 共同读取。

### 4.2 Reference Dataset

保存经过单位统一的论文数据点及其来源元数据。论文图表数字化得到的数据必须与人工录入或论文附带的原始数据区分，并记录数字化误差。

参考数据分为标定集和盲测集。标定集可以用于确定台呢摩擦、球球恢复系数、库边参数等材料常数；盲测集不得参与调参，只用于最终验收。

### 4.3 Simulation Recorder

按固定物理 tick 记录状态，不以渲染帧作为采样时钟。每条记录至少包含：

- 模拟时间和 tick 编号；
- 球的位置、线速度、线加速度；
- 三维角速度和滑动/滚动状态；
- 球杆状态及击球冲量；
- 球球、球库、球袋接触事件、法线和冲量；
- 系统线动量、角动量、动能和最大穿透深度。

渲染帧可以额外关联到最近的物理状态，用于生成失败录像，但不能替代权威物理记录。

### 4.4 Physics Analyzer

分析器把仿真结果与解析期望或参考数据进行时间和坐标对齐，计算：

- 动量、角动量和能量变化；
- 轨迹位置 RMSE 与最大偏差；
- 停止时间、停止距离和滑动到滚动的转换点；
- 碰撞前后线速度、角速度、分离角和事件时间；
- 库边反弹速度、角度和旋转变化；
- 袋口通过/拒绝分类以及边界距离；
- 穿透深度、漏碰、重复冲量和非法状态。

### 4.5 Acceptance Runner

运行器选择场景、驱动相同的生产物理核心、调用分析器并根据证据等级应用验收规则。它输出机器可读数据和人工报告，并提供单场景重放命令。

完整数据流为：

`公开实验 → 标准场景 → 自动运行 → 逐 tick 状态 → 指标计算 → 容差判定 → CI 报告`

## 5. 验收规则

### 5.1 解析正确性硬门槛

- 不出现 NaN、无穷大或非法状态。
- 无外力时不凭空增加线动量或角动量。
- 摩擦和非弹性碰撞不能增加系统总能量。
- 碰撞结果不受球编号和碰撞对遍历顺序影响。
- 改变渲染帧率、主循环运行速度或机器负载不能改变物理结果。
- 同一可执行文件在相同输入和步数下必须确定性复现。
- 最大穿透深度不得超过求解器明确规定且记录在测试元数据中的数值容差。

跨平台浮点结果允许使用明确的数值容差比较；同一平台、同一构建的确定性检查要求逐字段一致。

### 5.2 公开实验初始容差

| 现象 | 指标 | 初始上限 |
|---|---|---:|
| 自由滚动 | 停止时间、停止距离 | 5% |
| 滑动到滚动 | 转换时间、转换位置 | 7% |
| 球球碰撞 | 出射速度 | 5% |
| 球球碰撞 | 出射角 | 2° |
| 库边碰撞 | 反弹速度 | 7% |
| 库边碰撞 | 反弹角 | 3° |
| 高低杆、侧旋 | 速度、旋转或偏转量 | 10% |
| 完整轨迹 | 位置 RMSE | 5 mm |

这些数值是首次接入数据时的工程上限，不覆盖论文自身的不确定度。实际判断使用以下规则：

1. 如果论文给出的置信区间或测量不确定度大于初始上限，场景采用论文区间并在报告中标明原因。
2. 如果论文精度更高，应在模型稳定后逐步收紧，但不得为了让失败场景通过而扩大容差。
3. 数字化误差必须与测量误差分别保存，并通过误差传播形成最终区间。
4. 只有盲测集满足验收条件，才能声称模型符合公开实验。

### 5.3 多球和混沌场景

开球等混沌敏感场景不要求逐球轨迹与某一场真实开球逐帧重合，而验证：

- 无穿透、漏碰、重复冲量和能量爆炸；
- 球编号、渲染帧率和执行速度不引入系统性偏差；
- 使用固定随机种子时可重放；
- 多次运行的散布范围、静止时间和进袋比例满足明确的统计区间。

## 6. 场景矩阵

### 6.1 基础运动

- 多档初速度的直线滑动、滚动和停止。
- 正旋、逆旋、侧旋及组合旋转。
- 滑动到纯滚动的状态转换。
- 极低速度下稳定停止，不抖动、不反向。

### 6.2 球杆击球

- 中心击球的冲量和初速度。
- 不同高度击点产生的高杆和低杆。
- 左右偏心击球产生的侧旋。
- 接近球边缘时的滑杆边界。
- 力度、球杆速度和母球动能之间的关系。

### 6.3 球球碰撞

- 正碰、薄碰和多档入射速度。
- 母球带高杆、低杆或侧旋的碰撞。
- 静止球、运动球和双方均带旋转的情况。
- 重叠、刚好接触和高速跨步等数值边界。
- 三球直线传递、球堆和近似同时碰撞。

### 6.4 库边碰撞

- 垂直撞库和多种入射角。
- 不同速度下的反弹损耗。
- 顺塞、反塞对反射角和出射速度的影响。
- 连续多库、贴库球和库角附近碰撞。

### 6.5 袋口和台面边界

- 正面、斜向和擦边进袋。
- 不同速度和旋转下的进袋边界。
- 袋角碰撞、袋口反弹和拒球。
- 母球落袋后的状态处理。

公开袋口实验数据不足时，该组以 WPA 几何、接触物理和解析不变量为主，报告必须标为 C 级证据，不得宣称已经通过真实轨迹实验验证。

### 6.6 完整玩法和稳定性

- 开球、连续碰撞、进球和犯规流程。
- 不同渲染帧率、运行速度和机器负载下的一致性。
- 极端力度和非法输入的安全处理。
- 固定种子的长时间随机击球压力测试。

每个关键场景同时提供直接驱动物理核心的精确测试和经自动化协议操控完整游戏的 E2E 测试。两类测试共享场景定义和验收指标，避免测试替身与生产行为脱节。

## 7. 执行分层

### 7.1 PR 快速检查

运行解析正确性、关键论文基准和历史故障回归，目标是数分钟内完成。任何硬门槛失败均阻止合并。

### 7.2 完整物理回归

运行全部论文数据、场景矩阵和完整游戏 E2E，适合合并前手动触发和每日定时运行。

### 7.3 长期压力测试

运行大量随机击球、密集球堆和重复开球。所有随机测试必须记录种子，失败后能够单场景重放。

## 8. 输出与错误分类

每次运行输出：

- JSON/CSV：场景输入、逐 tick 状态、指标、阈值、证据来源和通过状态；
- 人工报告：仿真与论文数据叠加图、误差曲线、碰撞事件时间线和失败摘要；
- 失败重放信息：场景标识、随机种子、构建版本和单场景命令；
- 失败时的截图或录像。数值记录始终保留，视觉产物按失败策略保留。

失败分为：

- `NUMERICAL_FAILURE`：NaN、穿透、漏碰、重复冲量或能量爆炸；
- `MODEL_MISMATCH`：仿真稳定，但与公开实验超出允许区间；
- `NON_DETERMINISTIC`：相同输入得到不同结果；
- `INTEGRATION_MISMATCH`：物理核心测试通过，但完整游戏 E2E 不一致；
- `REFERENCE_LIMITATION`：数据不足、实验条件无法还原或证据等级不够。

`REFERENCE_LIMITATION` 是未验证状态，不得计为通过，也不应在没有新的参考证据时阻塞与该证据无关的回归检查。

## 9. 历史快照的角色

通过解析约束和公开实验验证的场景可以固化为 golden trajectory，用于快速发现后续回归。快照只能证明行为是否发生变化，不能反过来证明物理真实。

当物理模型被有意改进时，必须先展示新结果在参考指标上的改善，再更新快照；不得仅因快照失败直接覆盖基准。

## 10. 完成标准

验证体系达到可用状态需要满足：

1. 五个验证模块具有版本化接口，底层测试和完整游戏 E2E 使用同一生产物理核心。
2. 每个物理子系统至少有解析测试、公开实验测试或明确的 `REFERENCE_LIMITATION`。
3. 标定集与盲测集物理隔离，报告分别展示结果。
4. 所有失败能够自动分类并通过记录的场景和种子重放。
5. PR 快速检查、完整回归和长期压力测试均可自动运行。
6. 报告能够从指标追溯到输入场景、物理版本和公开证据。
7. 只有硬门槛全部通过且盲测实验处于允许区间，项目才可声明相应物理现象“符合公开实验”。
