# 第三阶段主题 7：完整游戏集成与最终验收设计

日期：2026-07-14

## 1. 目标

证明各物理主题通过真实用户操作路径稳定驱动完整游戏，并建立模型成为生产默认值的最终门槛。

## 2. 双路径同核心

精确 scenario 与自动化用户操作只在输入构造层不同，均驱动同一个 `GameRuntime` 和 `PhysicsStepper`。首次物理状态一致时，后续权威 trace 必须一致。测试不得维护替代物理实现。

完整矩阵覆盖击球偏移、台面状态转换、球球与球库接触、袋口边界、开球、连续进球、犯规、帧率、执行负载和固定种子压力运行。游戏规则只消费物理事件。

## 3. 执行层级

PR 快速检查运行解析不变量、代表性 calibration、已晋级模型回归和少量 E2E。完整回归运行所有数据、器材 profile、场景矩阵、确定性和优化前后报告。长期任务运行重复开球、随机击球、性能、内存和 artifact 趋势。

## 4. 模型晋级

候选成为生产默认值必须同时满足：

1. calibration 目标和解析硬门槛通过；
2. 公式、参数和代码已冻结；
3. 验证集无未解释新 regression；
4. mismatch 只因真实解除条件而减少；
5. 完整游戏无 integration mismatch；
6. 性能满足预注册预算；
7. 报告可追溯到模型、参数、数据、构建和场景。

趋势证据或不可转换器材不能因游戏观感自然而升级为“符合公开实验”。

## 5. Golden trajectory

只有通过解析或实验验收的场景可成为 reality golden。模型改进必须先展示相对真实基准的改善，再更新快照。未通过真实验证的诊断轨迹标记为 behavior snapshot。不得仅因快照失败批量覆盖。

## 6. 报告与发布

报告包含模型与参数摘要、calibration/validation/spent 状态、主题指标、硬门槛、严格失败分类、优化前后差异、性能、确定性、重放命令和视觉 artifact。

自动化协议保持版本化；旧场景缺少新 profile 时显式使用对应版本默认值。默认模型切换独立提交并可回滚，发布前保存旧新模型完整对照。实验调试入口不得进入普通玩家路径。

## 7. 完成标准

第三阶段只有在八个主题各自完成、完整游戏 E2E 与压力测试通过、生产模型完成冻结与验证、失败和证据等级无夸大时才整体完成。单个公式或单篇论文通过不代表游戏物理全部真实。
