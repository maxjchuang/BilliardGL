# BilliardGL 第三阶段：物理优化路线总设计

日期：2026-07-14

## 1. 目标

第三阶段在第一阶段的自动化、逐 tick telemetry 与验收能力，以及第二阶段的公开实验数据包之上，优化实际生产物理。目标不是让少量场景看起来更自然，而是建立一套可解释、可拟合、可盲验、可回归的 2.5D 台球物理核心。

生产物理必须同时服务直接场景测试和完整游戏 E2E。任何“符合真实世界”的结论都必须来自解析约束、已审计 calibration 数据和未参与模型选择的验证数据；视觉观感只作辅助。

## 2. 边界

本阶段包含：

- 台面滑动、滚动、停止和三维角速度；
- 球杆击点、冲量、旋转和滑杆边界；
- 球球、球库及库鼻接触；
- 袋口几何、捕获和拒球；
- 连续碰撞、多接触、开球和确定性；
- 完整游戏集成、性能和实验验收。

本阶段不包含完整跳球、扎杆、腾空、有限元形变或通用三维刚体引擎。需要这些能力的输入必须明确报告 unsupported 或 `REFERENCE_LIMITATION`，不得静默投影成平面运动。

## 3. 顶层主题

第三阶段按物理依赖拆成八个主题：

| 顺序 | 主题 | 核心交付 |
|---:|---|---|
| 0 | 调优治理与参数架构 | calibration-only 调参、冻结记录、验证集审计、器材与材料 profile |
| 1 | 单球台面运动与旋转 | 滑动、纯滚动、停止、角速度和状态转换 |
| 2 | 球杆—母球接触 | 物理球杆输入、偏心击球、stick/slip/miscue |
| 3 | 球—球碰撞 | 恢复、摩擦、旋转传递和不同材料/质量 |
| 4 | 球—库边碰撞 | 速度损失、反弹角、库鼻高度和旋转耦合 |
| 5 | 袋口与台面边界 | 权威几何、库鼻接触、捕获/拒球状态机 |
| 6 | 求解器与多接触 | 连续碰撞、contact island、穿透修正和确定性 |
| 7 | 完整游戏集成与验收 | E2E、模型晋级、golden trajectory 和发布门槛 |

依赖关系为：

```text
主题 0：参数与验证治理
        ↓
主题 1：台面运动与旋转
   ↙         ↓          ↘
主题 2      主题 3       主题 4
球杆接触    球球碰撞      库边碰撞
   ↘         ↓          ↙
      主题 5：袋口边界
             ↓
      主题 6：多接触求解
             ↓
      主题 7：完整游戏验收
```

主题 2、3、4 在主题 1 和共享参数架构完成后可以独立设计和实施；主题 5 复用库边接触；主题 6 组合所有单接触模型；主题 7 是生产默认值晋级的最终门槛。

## 4. 统一生产架构

生产物理逐步形成以下边界：

```text
PhysicsStepper
 ├─ SurfaceMotionModel
 ├─ CueContactModel
 ├─ BallBallContactModel
 ├─ CushionContactModel
 ├─ PocketBoundaryModel
 └─ MultiContactSolver

PhysicsProfile
 ├─ BallProperties
 ├─ SurfaceProperties
 ├─ CueProperties
 ├─ CushionProperties
 └─ SolverSettings
```

`PhysicsStepper` 是固定物理 tick 的唯一编排入口。各模型只负责自己的力或接触响应，通过统一 contact 和 telemetry 数据结构通信。游戏规则只消费稳定物理事件，不重复判断碰撞和进袋。

`PhysicsProfile` 使用带显式单位的值对象管理生产默认参数和实验场景覆盖。Chinese Pool 默认 profile 与论文器材 profile 分离；实验覆盖不得修改生产默认值。

生产状态暂时保留现有 `cm`、`s`、`rad/s` 单位，字段和参数必须带单位后缀。论文公式在明确边界集中转换，不允许无来源、无单位的裸常量。

## 5. Calibration、验证与数据状态

仓库按既定策略提交全部计算数据，因此不存在密码学意义的数据保密。第三阶段采用流程隔离与审计隔离：

1. calibration runner 只能消费 `calibration` 分区；
2. 公式、参数、代码 SHA、calibration 报告和验收目标在验证前写入冻结记录；
3. 验证 runner 只接受已冻结候选；
4. 验证结果不自动反馈给优化器；
5. 一旦某验证数据被用于选择公式或参数，它必须标记为 `spent`，以后只能作为回归数据；
6. 最终强真实性声明需要未参与选择的新确认数据；
7. 所有失败和失败后的模型版本完整保留。

第二阶段的 holdout 已经执行过，但当时未据此优化生产物理。第三阶段将其称为“预注册验证集”，不会夸大为完全未知的双盲数据。

## 6. 候选模型生命周期

每个主题遵循同一闭环：

```text
物理假设或论文模型
  -> calibration-only 实现与拟合
  -> 解析/数值硬门槛
  -> 候选模型冻结
  -> 预注册验证集运行
  -> 完整游戏 E2E
  -> 晋级、保留失败或开启新模型版本
```

材料参数可以使用 calibration 拟合；数值容差、停止阈值和迭代上限只能通过稳定性、精度与收敛测试确定，不能用来吸收实验误差。增加模型自由度必须有物理证据并形成新公式版本。

## 7. Telemetry 与错误分类

每个物理 tick 继续记录位置、线速度、线加速度、三维角速度、运动状态、能量、动量、接触法线、冲量和穿透。新增模型必须扩展同一权威 trace，不建立测试专用状态。

错误严格分账：

- `MODEL_MISMATCH`：模型稳定但超出实验区间；
- `REFERENCE_LIMITATION`：证据或可表达条件不足；
- `NUMERICAL_FAILURE`：NaN、穿透、漏碰、重复冲量或能量爆炸；
- `INTEGRATION_MISMATCH`：精确场景与完整游戏路径不一致；
- `NON_DETERMINISTIC`：等价或重复输入产生不允许的差异。

任何分类都不得吸收另一类失败。旧 mismatch 或 limitation 只有在解除条件被真实满足并有新报告时才能删除。

## 8. 验收层级

### PR 快速检查

- 解析不变量和关键单元测试；
- 每个已实施主题的代表性 calibration 场景；
- 已晋级模型的关键验证回归；
- 少量完整游戏 E2E；
- schema、编码、构建与协议兼容性。

### 完整物理回归

- 所有 calibration、预注册验证和 spent 回归数据；
- 全部器材 profile 与场景矩阵；
- 优化前后数值报告；
- 确定性、时间步收敛、截图、录像和完整 trace。

### 长期压力测试

- 固定种子的随机击球和重复开球；
- 最大穿透、迭代次数、停止时间和失败率；
- 性能、内存和 artifact 体积趋势。

## 9. 主题完成与生产晋级

单个主题完成要求：

1. 设计和实施计划已评审；
2. production 与测试使用同一模型；
3. calibration 目标和解析硬门槛通过；
4. 候选公式与参数已冻结；
5. 验证报告严格分账；
6. 新能力通过 E2E；
7. 文档、参数来源和重放命令完整；
8. 没有通过扩大实验容差或删除数据制造成功。

生产默认值晋级还要求完整游戏无回归、性能满足预注册预算，并保存旧模型和新模型的完整对照。单篇论文或单个公式通过不代表整个游戏物理完成。
