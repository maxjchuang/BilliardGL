# Phase 0 现有资产审计与迁移矩阵

日期：2026-07-27
审计范围：`src/Billiards/obj/`、`src/Billiards/tex/`、当前渲染资源绑定、1024×768 默认实机截图
审计性质：技术与生产适用性审计，不构成法律意见

## 1. 审计方法与基线

本次通过 OBJ/MTL 文本统计、文件元数据、渲染资源引用和应用内 framebuffer 截图交叉检查。默认场景使用：

```sh
./build/Billiards --windowed --width 1024 --height 768 \
  --screenshot /tmp/billiardgl-art-audit/default.ppm
```

截图只存于 `/tmp`，未提交仓库。审计画面呈现一张近乎铺满屏幕的球台、纯色台呢、深色木质库边、简单球体高光、平面投影阴影、灰色房间与 GLUT 文本 HUD。默认 Observe 场景没有显示球杆和台灯实体。

OBJ 统计中的三角形数是按 `n` 边面拆为 `n-2` 的估算值；运行时加载器可能因顶点属性拆分产生不同的 GPU 顶点数。

坐标观察：所有 OBJ 均以 `Y` 为竖直轴；球台长边沿 `Z`，短边沿 `X`。旧球台包围盒不是物理可打区域。

### 2.1 球台关键问题

- 当前物理台面为 `127 × 254 cm`，台高为 `85 cm`，球直径为 `5.715 cm`。
- 旧球台可见台面高度为 `86.483976 cm`，且必须使用 `X=127/121.5311`、`Z=254/249.0196` 的非等比缩放，才能让库边净空贴合物理范围。
- 这种补偿会改变木纹比例、袋口轮廓和库边截面，不适合继续作为高质量资产基础。
- 仅有两个材质段，无法独立控制台呢、木饰面、橡胶库边、金属角件、袋口皮革、袋内壁和台体。
- 旧模型的 60k 三角形没有换来袋口近景所需的清晰分层；应将预算重新分配到袋角、库边鼻口和倒角轮廓。

### 2.2 球杆关键问题

- 源模型长约 `144.77`，当前代码还需要根据最小 `Z` 推算杆头偏移，说明原点不是稳定的击球接触基准。
- OBJ 的 `usemtl` 名称带 `cue5:`，MTL 的 `newmtl` 名称带 `cue1:`，资源绑定依赖顺序和硬编码区段，生产风险高。
- 当前最多只绑定两张主要纹理，并将母球纹理临时用于球杆的一段；无法稳定表现皮头、先角、前节、后把、漆面和接牙。

### 2.3 房间与装饰关键问题

- 房间不是资产，而是 `1000 × 1000 × 400 cm` 的立即模式平面；地面和墙面是纯色，只有天花板绑定纹理。
- 长椅无 UV，运行时直接使用黑色纹理；衣柜使用单张贴图。两者对默认构图贡献很低，却扩大了资源加载和授权面。
- 没有可见矩形台灯几何；单个全向固定管线光位于桌面上方，环境光为 `0.65`，削弱了主次和接触感。

## 3. 纹理清单

纹理目录约 `132 MB`，均为无 PBR 通道的 24-bit BMP，另有一张旧 JPEG。主要类别：

| 类别 | 文件 | 分辨率 / 数量 | 当前使用 | 结论 |
| --- | --- | --- | --- | --- |
| 球面 | `B1.bmp`–`B16.bmp` | 约 1600×799，共 16 张 | 是 | 重绘为原创编号图集或分层贴花；旧图只作语义对照 |
| 球台 | `1.bmp`, `2.bmp` | 2000²、2600×1310 | 是 | 木纹有明显摄影照明，台呢为纯绿色；全部替换 |
| 球杆 | `3.bmp`, `4.bmp` | 2000×2578、1024² | 是 | 第一张包含大量无效黑区，第二张近乎纯色；替换 |
| 房间 | `ceiling.bmp` | 2000×800 | 是 | 非无缝且缺少法线/粗糙度；替换 |
| 装饰 | `black.bmp`, `5.bmp` | 256²、512² | 是 | 仅迁移期占位；替换 |
| 粒子 | `flame2.bmp` | 32² | 被资源系统强制加载 | 与台球视觉方向不一致；正式路径移除 |

材质仅包含传统 `Ka/Kd/Ks/Ns`，纹理写在 `map_Ka`。没有 base color 的色彩空间声明，也没有 normal、roughness、metallic、AO 或 emissive 通道。BMP 没有 alpha 和压缩，16 张球纹理磁盘占用约 59 MB，但信息高度重复。

## 4. 当前实机视觉问题

| 现象 | 根因 | 优先级 | 可验证的修复方向 |
| --- | --- | ---: | --- |
| 球像塑料或漂浮 | 单一通用高光、无环境反射、平面投影阴影 | P0 | 台灯反射连续；球下接触阴影不分离、不穿台呢 |
| 台呢为大块纯绿 | 单张纯色纹理，无微表面与方向性 | P0 | 常规距离无噪点，近景可读到细纤维方向和柔和粗糙度变化 |
| 袋口像黑环或贴图洞 | 两材质球台无法分出皮革、内壁、落袋深度 | P0 | 袋口特写能看到库边鼻口、皮革边、暗部内壁与遮蔽层次 |
| 木边黑且重复 | 烘焙式摄影木纹叠加错误光照，无 roughness | P0 | 木纹尺度连续，反射随观察角变化，接缝处不跳变 |
| 房间扁平 | 高环境光、无灯具、墙地纯色、无空间层次 | P1 | 球台比背景亮 2–3 EV；灯具和背景轮廓可见但不抢主体 |
| 默认构图缺乏击球感 | 固定 60° FOV，高位远观，球台裁切拥挤 | P0 | 四类镜头按目标文档构图并纳入六场景截图 |
| HUD 像调试信息 | 位图字体和裸文本缺少层级 | P1 | Phase 3 由产品 HUD 解决；美术仅预留安全区和对比度 |

## 5. 授权与来源风险

仓库历史只能追溯到 2018 年导入，未找到作者、许可文本、采购记录或来源 URL。OBJ 分组和材质名称出现 `ARCHMODELS`，部分文件带 3ds Max / Maya 导出痕迹，`B2.jpg` 元数据指向 2010 年 Photoshop。它们不足以证明侵权，也不足以证明有发布权。

处理规则：

1. 项目负责人为每个 legacy 文件补齐 `source / author / license / acquisition date / redistribution` 记录。
2. 无法提供书面发布权的资产标记为 `replace_before_release`。
3. 新资产不得从旧网格重拓扑、烘焙或描摹纹理；只读取物理尺寸和功能分件要求。
4. 竞品图片只能用于观察材质现象、构图和可读性，禁止贴入纹理、描图、复刻品牌轮廓或 UI trade dress。

## 7. 迁移建议

- LegacyRenderer 继续读取旧 OBJ/BMP，ModernRenderer 只读取有 manifest 和授权元数据的新 glTF/PNG。
- 新球台先以灰模验证物理对齐；对齐冻结后才进入高模、UV 与材质制作。
- 在迁移完成前不要删除旧文件，以保留可回滚路径；但发布打包清单必须能排除无授权结论的旧资源。
- 资产比较以同一物理快照和同一镜头完成，避免把镜头改善误判为材质改善。
